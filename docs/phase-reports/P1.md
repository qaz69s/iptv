# P1 阶段报告：播放列表导入、频道浏览、基础播放

日期：2026-11-16　应用：StreamBox Player（debug 包 `com.streambox.player.debug`）

P1 分两次提交完成：P1a（`5173eda`，解析 / 数据 / 导入 / 播放列表与频道界面）与 P1b（本次，播放页、测试、文档）。

## 做了什么
### P1a（5173eda）
- **core:parser**（纯 Kotlin）：M3U/M3U8 流式解析器（`#EXTM3U` 头属性、`#EXTINF` 属性、`#EXTGRP`、`#EXTVLCOPT` UA/Referer、catchup 属性、BOM / CRLF / 坏行跳过计数），50 余项样例测试 + 10 万行性能测试（JVM）。
- **core:network**：OkHttp 下载（gzip、重定向、UA）、`CleartextGuardInterceptor` 按播放列表在每一跳拦截明文 http（证书校验始终开启），MockWebServer 测试。
- **core:database**：Room（Playlist / ChannelGroup / Channel + FTS4），schema 已导出入库；频道分代（generation）导入，校验后原子切换，失败不影响旧数据。
- **core:data**：仓库实现；导入管线（URL 下载或 SAF 读取 → 流式解析 → 分批写入 → 校验提交），应用级作用域运行，可取消；导入状态（连接中 / 进度 / 收尾 / 成功 / 失败原因 / 已取消）。
- **core:player**：`PlaybackController` 单例（Media3 ExoPlayer），按 URL 选 HLS / DASH / RTSP / Progressive，无扩展名 URL 容器不识别时自动改走 HLS 一次；按播放列表注入 UA / Referer 与明文开关；BEHIND_LIVE_WINDOW 自动回到直播点；错误码映射为 HTTP 状态码 / 超时 / 网络 / 明文被拒 / 解码 / 格式。
- **feature:playlist**：添加播放列表（URL / 本地文件；Xtream 占位提示 P6）、导入进度页（取消 / 重试 / 去看频道）、播放列表管理（刷新、删除、单列表明文开关）。
- **feature:channels**：空状态引导、分组 chips、分页频道列表（台标、频道号）。

### P1b（本次）
- **feature:player**（新模块）：替换 app 中的 PlayerPlaceholder。
  - 路由 `PlayerRoute(channelId, groupName?)`；频道页点击时把当前分组经路由传入，播放页在同一分组内循环切台（无分组 = 全部频道）。
  - 全屏画面：media3-ui-compose `ContentFrame`（SurfaceView，按比例 Fit）。
  - 覆盖层：频道号 + 名称、返回按钮、上 / 下切台按钮（触屏）、操作提示；4 秒自动隐藏，点击切换显示，TV 上 OK / INFO 显示；有错误时常驻。
  - 缓冲转圈；错误面板显示具体原因（HTTP 状态码、超时、网络、明文被拒、解码、格式、频道不存在）+ 重试（TV 上重试按钮自动获得焦点）。
  - 切台：手机上下滑动（上滑 = 下一台）、覆盖层按钮；TV 方向键上 / 下、KEYCODE_CHANNEL_UP / DOWN。连续快速按键逐台前进（串行处理）。
  - 播放 / 缓冲时 keepScreenOn；进入时隐藏系统栏（滑动可临时呼出），手机 / 平板强制横屏（sensorLandscape），离开恢复原方向与系统栏。
  - 生命周期：ON_START 播放、ON_STOP 与离开页面 `release()`（回到前台从直播点重新播放），ViewModel 销毁时再 `release()` 兜底。当前频道 id 存 SavedStateHandle，进程重建后回到最后观看的频道。
  - 中英文字符串。
- **修复**：频道页"选中分组在刷新后消失时列表为空"——分页列表现在与 chips 使用同一个"有效分组"（不存在则回落到全部；分组重新出现时恢复原选择）。
- **测试**（新增 38 项）：PlayerViewModel 9（fake PlaybackController）、AddPlaylistViewModel 8、ImportProgressViewModel 3、PlaylistsViewModel 3、ChannelsViewModel 6（含分组回落）、AddPlaylistUseCase 9（含 4 个参数化 URL 校验）。
- **文档**：本报告、README、ARCHITECTURE（新模块与播放生命周期）、implementation-plan（新依赖与 P1 状态）。

## 已知问题
1. **Coil 台标请求不受"按列表明文开关"约束**：频道列表的台标通过 Coil 的全局 OkHttp 客户端加载，未挂 `CleartextGuardInterceptor`，所以即使列表未允许明文，http 台标仍会被加载（只影响图片，不影响播放与列表下载）。计划 P3 为图片请求按所属列表打标签后拦截。
2. **Room DAO 无 JVM 测试**：DAO / 迁移测试写在 androidTest（需模拟器或真机）；沙箱只跑 JVM 测试，导入管线用 `FakePlaylistImportStore` 覆盖。
3. **尚未真机 / 模拟器验证**：沙箱为 aarch64、无模拟器；APK 能构建但从未安装运行。播放页的手势、沉浸、横屏、ContentFrame 渲染均只经编译与 ViewModel 单测验证。
4. **TV 抽屉与焦点待验**：TV 上 NavigationDrawer 始终存在（非一级页面时内容为空），以保证 NavHost 不被重建；需在 TV 上确认引导页 / 添加页 / 播放页焦点正常，播放页方向键上 / 下被用于切台，因此覆盖层中只有"重试"按钮可聚焦。
5. **手机底部可能多出系统栏空白**：频道 / 播放列表页的 Scaffold 嵌在 NavigationSuiteScaffold 内，底部 inset 可能被计算两次，需真机确认。
6. 播放页在手机 / 平板上强制横屏；若希望竖屏也能看（小窗式），需在 P2 与 PiP 一起调整。
7. 离开页面或切后台即释放播放器，返回时重新起播（直播从当前直播点开始，有一次重新缓冲）；P2 后台播放会改变这一点。
8. 进入播放页时若频道在此期间被刷新删除，显示"频道不存在"；重试会再查一次。

## P1 验收清单（真机 / 模拟器，需用户）
手机：
- [ ] 安装 APK，首启引导 → 免责声明 → 自动进入"添加播放列表"。
- [ ] 添加一个 https M3U URL，进度页显示进度并成功；"去看频道"出现分组与频道。

- [ ] 选一个分组 → 点频道：进入全屏横屏、系统栏隐藏、出现频道号 + 名称，约 4 秒后覆盖层消失；点画面再次出现。
- [ ] 上滑 / 下滑切到同分组的下一 / 上一台，首尾循环；覆盖层上 / 下按钮同样有效。
- [ ] 播放一个无效地址（如 404）：显示"服务器返回 HTTP 404"+ 重试按钮。
- [ ] 播放中屏幕不熄灭；按 Home 再回来会重新起播；返回频道页后恢复竖屏与系统栏。
- [ ] 刷新播放列表使当前选中分组消失：频道页回到"全部"且列表不为空。
- [ ] 观察频道页 / 播放列表页底部是否有多余空白（已知问题 5）。
TV（或 TV 模拟器）：
- [ ] 桌面出现 banner，可启动；引导页 / 添加页焦点可用遥控器操作（已知问题 4）。
- [ ] 进入播放：方向键上 / 下与频道 +/- 键切台；OK 显示覆盖层；返回键退出播放。
- [ ] 错误时"重试"按钮自动获得焦点，按 OK 重试。
